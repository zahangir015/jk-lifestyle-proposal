Boundary rule

No cross-domain DB access

Each domain owns its data. Interactions happen through APIs or domain events, keeping integration seams explicit and replaceable.

Evolution rule

Modular now, extract later

Clinical and AI/Food Recognition are the likely first candidates for independent services if workload isolation or compliance requirements increase.

Data rule

Events captured from day one

Operational events needed for alerts, analytics and future prediction are written once and consumed by multiple downstream capabilities.

Migration rule

Parallel run before cutover

No major system changes directly against live business operations without rehearsal, reconciliation, rollback and business-owner sign-off.

05

Integration, sync & real-time

Design for intermittent connectivity, event-driven updates and controlled external dependencies.

Retail, clinical and device workflows cannot depend on perfect internet connectivity or tightly coupled vendor APIs.

Offline POS

Local-first transaction capture

  1. Outlet POS keeps local catalogue, price list and open-shift data in SQLite.
  2. Sales are written locally first and queued for background synchronization.
  3. Stock decrements are append-only events, not direct quantity overwrites.
  4. If replay drives authoritative stock negative, the completed sale is retained and flagged for inventory review.
  5. Cash/shift reconciliation remains independent from stock sync so closing is not blocked by an outage.
Wearables / CGM

Broad platform integrations first

  1. Health Connect and HealthKit are the default ingestion hubs.
  2. Direct vendor API or BLE is used for devices that are not covered by platform health hubs.
  3. Manual entry remains available for every metric and uses the same backend endpoint.
  4. Near-real-time push is preferred; otherwise scheduled polling can match device cadence.
  5. Duplicate readings use source/time conflict rules; manual entries fill genuine data gaps.
Event backboneRabbitMQ first

Operational events feed multiple consumers without duplicating write paths. Kafka is deferred until event volume clearly justifies the operational overhead.

NotificationsDomain-event triggered

FCM/APNs for mobile push; WebSocket for OPD queue and live manager dashboards. Avoid polling where event-driven delivery is available.

Reliability controlsIdempotency + trace IDs

Offline sync and integrations require repeat-safe processing, correlation IDs and observable retry behavior during network or vendor failure.

Community feedHybrid consistency

User writes are immediately consistent; ranked-feed calculations happen asynchronously to avoid premature real-time ranking complexity.

06

Security, privacy & resilience

Security controls are architecture components, not release-time add-ons.

Health data, finance data and identity receive stricter controls than ordinary application content.

01

Three-dimensional RBAC

Authorization is scoped by Concern, Location and Function and enforced at the API gateway / service boundary, not only in the UI.

02

Strong authentication

Mandatory 2FA for staff/admin users. Customer/patient access uses OTP-based login suitable for lower-friction consumer onboarding.

03

Encryption + health-data isolation

Encryption in transit and at rest, plus field-level encryption for sensitive EMR, device and care-plan fields.

04

Read and write auditability

Sensitive health-data access is logged on reads as well as writes, enabling traceable access review.

05

Consent as data

Consent is stored as an explicit, revocable record that governs community sharing, device data and analytics/AI use.

06

Continuous application security

Dependency scanning, SAST and OWASP controls are built into CI; independent VAPT is required before major production go-lives.

Backup / DRAutomated backups, restore testing, module-specific RTO/RPO and DR rehearsal before major releases.
Local resilienceDhaka flagship may use a local edge/cache node over secured VPN; other outlets rely on offline-first POS and background sync.
ObservabilityStructured logs, trace IDs, metrics, SLO dashboards, vulnerability backlog and monthly cost review.

Q

Concise board answers

Four high-impact questions, answered in operational terms.

These answers summarize controls already defined across architecture, delivery, risk management and operating-cost design.

Q10 · Project failure Three primary failure drivers to control

Dirty Odoo/Excel/master data → profile early, migrate in stages, reconcile and verify stock before cut-over. Clinical workflow churn → embed the Clinical SME, prototype early and sign acceptance criteria. Capacity/scope pressure → phase hiring, use specialist bridge support when needed, and enforce Definition of Done, change control and quarterly gates.

Q14 · Community moderation Automation flags; humans decide

Technology auto-flags health-misinformation patterns, while humans make moderation decisions through a Moderation Console under an SLA. Moderation tooling and minimum moderation capacity are hard Community go-live gates; health-content decisions are not delegated to AI alone.

Q15 · Dangerous alerts Clinician accountability with reliable escalation

A dangerous reading triggers the Alert Engine, which notifies the patient and creates the assigned clinician task in parallel. The clinician is accountable within a defined SLA; unacknowledged alerts escalate to the on-call supervisor. Queued events, idempotent retry, delivery monitoring, trace IDs and an audit trail protect reliability.

Q16 · Media & AI cost Control variable cost at every layer

Right-size compute with autoscaling limits; compress images, use CDN caching, adaptive-bitrate video and lifecycle/cold-storage rules; cache repeated/common meal recognition and batch non-urgent AI processing. Track storage/CDN/AI unit costs monthly and move from Buy to Build only when quality and economics justify it.

Risk controls

Architecture and budget controls are designed around the program's highest exposures.

The highest risks are hiring, dirty operational data, clinical workflow churn, scope expansion and security/compliance defects.

If Year-1 budget is constrained

Defer optional growth capabilities before weakening the foundation.

  • Community Platform / Education LMS
  • Deep Wearable/CGM integration

  • Franchise + Health Tourism/Sinbad integration

  • JK ID / SSO + API Gateway + Master Data
